# Code audit — November 2026

Read-only review of the Android app by six reviewers, then each high-impact claim was checked against the source.
Items marked **fixed** are in the `fix/project-audit-batch1` branch. Everything else is open and listed by priority.
Nothing here was run on a device; Android-side changes need a CI build and a device check.

## Fixed in this batch

- **Spot trade history skipped older fills** (`BinanceSync.kt`, `spotDailyPnl`): the first request had no `fromId`, so Binance returned only the newest 1000 trades and the cursor jumped past the rest. Paging now starts from `fromId=0` and moves upward. *Confirm on a live account with more than 1000 fills for one symbol.*
- **A balance-snapshot failure cancelled the P&L sync** (`BinanceSync.kt`, `BinanceSyncRunner.sync`): the snapshot now runs in `runCatching`, so the history still merges.
- **Null response stream in Binance statements** (`BinanceStatements.kt`): switched to `readBinanceBody`.
- **Indian financial year used UTC** (`CryptoTaxHistory.kt`, `CryptoTaxReportScreen.kt`): trades between 00:00 and 05:30 IST on 1 April were put in the previous year. The year is now computed in Asia/Kolkata.
- **Weekly AI report window on Sunday-start locales** (`AiTradingIntelligence.kt`): `firstDayOfWeek` is pinned to Monday.
- **Drawdown used entry order, not date order** (`TradingAnalyticsScreen.kt`): balances are sorted by date before the drawdown walk.
- **CSV formula injection** (`CryptoTaxCsv.kt`): text starting with `= + - @` or a tab is prefixed with an apostrophe. Real negative numbers are unchanged.
- **Export reported success with no file written** (`MainActivity.kt` backup, `BinanceStatementsScreen.kt` CSV, `CryptoTaxReportScreen.kt` year report): a null output stream now raises an error.

## Open — high severity

- **Backup restore is not atomic** (`Logic.kt`, `importBackup`): the journal and Binance data are written before the trade plans and reviews are parsed. A malformed plans section leaves the journal replaced while the UI says "Restore failed."
- **Corrupt review store overwrites all reviews** (`TradeReview.kt`, `TradeReviewStore.load`): a parse error returns an empty map, and the next save writes only the new review.
- **Spot fees included in futures net P&L** (`AnalyticsDomain.kt`, `summarizeExchangeOrders`): stable fees come from all fills, including Spot fills excluded from the netted orders.
- **Statement duplicates and stale pending rows** (`BinanceStatements.kt`): the id includes `txId` and `status`, so a pending deposit is never updated to completed, and a withdrawal is stored twice once its txId changes.
- **Fill ids differ between CSV and API import** (`BinanceFillCsv.kt` line ~78 vs `BinanceSync.kt`): the same trade imported both ways is counted twice.
- **Partial-start cycle drops realized P&L** (`BinancePositionJournal.kt`, `addOpen`): a closing fill seen first in a cycle is treated as an open and its P&L is ignored.
- **Spot symbols capped at 80 and pages at 100, silently** (`BinanceSync.kt`, `spotDailyPnl`): realized P&L for the rest is dropped with no error.

## Open — medium severity

- Commission on USDC pairs is never deducted from lot quantities (`BinanceSync.kt`, uses `removeSuffix("USDT")`).
- Risk limits accept `NaN` and `Infinity`, which silently disable the loss gates (`Logic.kt` import, `MainActivity.kt` Save).
- Restore leaves the risk-limit text fields showing pre-restore values, so the next Save overwrites the restored limits (`MainActivity.kt`).
- Live-trade errors are shown only when the text contains one of three keywords (`MainActivity.kt`).
- Risk gate reward is gross while risk includes fees (`TradeRiskGate.kt` ~line 88).
- Loss-streak counting drops undated trades instead of treating them as a break (`RiskAlerts.kt` ~line 89).
- Trade-idea "track" records the live price as entry even when price has run past the plan (`DailyTradeIdeasScreen.kt` ~line 933).
- Entry alerts only fire on the single latest 15-minute bar, so a delayed worker run loses them (`TradeIdeaNotifications.kt` ~line 129).
- Historical replay models post-target-1 exits differently from the live worker (`DailyTradeIdeasScreen.kt` ~line 830 vs `TradeIdeaNotifications.kt` ~line 191).
- Spot-only sync with a missing key permission cancels silently; a key edited without re-entering the secret is discarded but reported as saved (`BinanceSyncScreen.kt` ~line 155).
- Position journal header total excludes cycles with missing P&L without saying so (`BinancePositionJournal.kt` ~line 181).
- Negative fees (rebates) are dropped in the journal and in `AnalyticsDomain.kt` (`fee > 0.0`).
- CSV fill dedupe collapses separate same-second partial fills (`BinanceFillCsv.kt` ~line 72).
- Statement errors keep only the category name, so a rate-limit ban looks like a bad key (`BinanceStatements.kt`, `bestEffort`).
- A successful rotating batch counts as a failure and forces retries (`BinanceAutoJournal.kt` ~line 316).
- Trade-idea and risk-alert workers swallow every exception, including cancellation, with no log (`TradeIdeaNotifications.kt`, `RiskAlertNotifications.kt`).
- Trade-idea journal drops the oldest rows past 300, including open positions (`TradeIdeaPaperJournal.kt`).
- Saved AI report label comes from the live selection, not the requested analysis (`AiTradingIntelligence.kt` ~line 288).
- Stale "today" and "now" values captured with `remember` (`PremiumOverviewScreen.kt`, `TradingAnalyticsScreen.kt`).
- Mark-price stream and REST refresh race on `livePositions` (`PremiumOverviewScreen.kt`).
- Calculator inputs saved as `Float` lose precision (`Logic.kt`).
- Non-finite values reach `JSONObject.put` and break export (`Logic.kt`, `CryptoTaxHistory.kt`).
- Manual and Binance P&L collapsed with `toMap()`, so duplicate dates overwrite silently (`PnlReconciliation.kt`).

## Open — low severity

- Escaped `\$` shows literal text instead of counts in the P&L calendar panel (`MainActivity.kt` ~lines 989, 1005).
- Quote-asset list differs between two analytics screens (`SimplifiedTradingAnalyticsScreen.kt`).
- Ledger audit swallows comparison errors and clearing the source total is a silent no-op (`LedgerAuditScreen.kt`).
- Income CSV rejects the `date(utc)` header that the fill importer accepts (`BinanceIncomeCsv.kt` line ~43).
- Progress callback writes Compose state from an IO thread (`DailyTradeIdeasScreen.kt` ~line 405).
- `replaceFuturesYear` writes out-of-year keys if they are passed in (`BinanceSync.kt`).
- Notification prices use default `Double` formatting, which shows scientific notation for tiny prices (`TradeIdeaNotifications.kt`).
- Background worker leaves "Syncing" status set if an unexpected exception escapes (`BinanceAutoJournal.kt`).
